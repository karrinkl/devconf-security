# ЛР 31. Вопрос спикеру с защитой от XSS

Продолжение API конференции DEVCONF 2026 из ЛР 28. Добавлена форма «Вопрос спикеру»: текст сохраняется в MongoDB и сразу выводится на страницу. Это вариант 2, вектор атаки — вредоносный скрипт в тексте вопроса.

## Как устроена защита

Запрос проходит очистку до записи в базу. `lib/sanitize.js` через `sanitize-html` выбрасывает теги и их содержимое, в том числе `script` и `onerror`. На странице оставшийся текст кодируется (`escapeHtml`), а скрипт `public/questions.js` вставляет ответ API через `textContent`, а не через `innerHTML`.

`middleware/security.js` подключает Helmet. Политика CSP разрешает скрипты только со своего адреса: `script-src 'self'`. Заголовок HSTS не ставится, потому что стенд открыт по `http://localhost`: с ним браузер перестал бы открывать страницу.

Команда `npm run demo:unsafe` запускает тот же сервер с `SECURITY=off`: без очистки и без CSP. Она нужна один раз, чтобы снять скриншот атаки до защиты. В репозитории для проверки оставляют обычный запуск.

## Запуск

Нужен Node.js 18 или новее. MongoDB ставить не нужно.

```bash
cd "/home/capybarinka/bsuir/7 сем/Мередова_Майса/ИнИС/ЛР31/devconf-security"
npm install
npm run local
```

Страница: http://localhost:5000/questions

API спикеров из ЛР 28 на месте: http://localhost:5000/api/speakers

Остановка: Ctrl+C. `npm audit fix --force` не запускать.

## Что проверить

1. Отправить вопрос обычным текстом. Он появляется в списке под формой.
2. Отправить `<script>alert('XSS PoC')</script>` и `<img src=x onerror=alert(1)>`. Скрипт не выполняется. После очистки слишком короткий текст сервер отклоняет, оставшийся текст показывается как символы, не как разметка.
3. В инструментах разработчика, вкладка «Сеть», у ответа `GET /questions` есть `Content-Security-Policy` со `script-src 'self'` и `X-Frame-Options`.
